## Executive Summary — 규율은 이미 존재한다, 갭은 *가장 새로운* 서브시스템에 몰려 있다

이 코드베이스는 성숙한 방어 규율을 갖고 있다 — atomic write, lost-wakeup 수정, wire-format self-contained 계약, unlink-under-reader 레이스 봉합. **과거 봉합은 전부 회귀 없이 건재**. 신규 발견의 무게중심은 **확립된 규율이 아직 소급되지 않은 최신 표면** — 멀티 에이전트 레지스트리(`agents_live.py`), `code_index`, `fetch` — 이다.

네 메타 패턴이 심각한 발견을 관통한다:

1. **문자열이 있어야 할 자리에 타입이 없음** — overflow 분류·provider kwargs가 예외 문자열 정규식에 의존 (L-1, L-25, L-26).
2. **손으로 복제한 번들은 썩는다** — 런타임 배선 5중 중복(S-11)이 web 세션 hooks 유실(S-2)로 이미 갈라짐.
3. **격리는 흩어져 있고 opt-in이다** — 새 변이 도구가 무-confine로 출하 → `fetch` SSRF (C-1), 틸드 우회 (C-3).
4. **보안 기본값이 스스로의 전제를 위반** — 웹서버 기본 `0.0.0.0` (C-4). board와 결합 시 원격 RCE → **경계 A**.

## ① 네트워크 노출 & 인증

### [P2] C-4 · 웹 UI가 LAN 전체(0.0.0.0)에 기본 바인드 = 원격 RCE  🔗경계 — ✅ RESOLVED (v8.7.0)
> 기본 `--host 127.0.0.1`, LAN 은 opt-in. 상세: `docs/boundary-A-security-lockdown-plan.md`.
`main.py:1755` (`--host` 기본 `0.0.0.0`, help="LAN") · `main.py:2184`
- **Impact**: LAN 어느 기기든 서버 도달 → `/api/input`이 AgentLoop 구동 → 임의 셸. 32바이트 토큰은 강하나 URL 쿼리·stdout에 실려 프록시 로그·브라우저 히스토리·Referer로 샌다.
- **Fix**: 기본 `127.0.0.1`, LAN 바인드는 명시 opt-in. 토큰을 `Authorization: Bearer` 헤더로. 최소한 `Referrer-Policy: no-referrer` + CSP. → **경계 A**(board와 조율).

### [P2] C-5 · 비밀 토큰이 모든 엔드포인트의 쿼리스트링에 실림  🔗경계 — ✅ RESOLVED (v8.7.0)
> HttpOnly `act` 쿠키 핸드셰이크(`_AuthMiddleware`) + app.js 토큰 미부착 + 주소창 strip + `Referrer-Policy: no-referrer`. 서버는 `?token=` 도 계속 수용(부트스트랩/툴링, 누출 무증가).
`web/server.py` — 모든 인증 라우트 `token: Query(...)`
- **Impact**: 쿼리스트링은 프록시/uvicorn 액세스 로그·브라우저 히스토리에 남고 외부 리소스로 Referer 전달. SSE URL에도 마스터 토큰 노출.
- **Fix**: 토큰을 헤더로. EventSource가 쿼리를 강제하면 단명·1회용 스트림 티켓 발급. 액세스 로그에서 쿼리 제외.

### [P3] C-11 · --trust-local + LAN 바인드 조합 풋건  🔗경계
`web/server.py:283-287, 402-423`
- **Impact**: 신뢰는 client host가 loopback일 때 부여 — loopback 뒤 게이트웨이 배치에서만 안전. LAN 바인드 시 로컬 무권한 프로세스가 인증 완전 우회.
- **Fix**: `--host`가 loopback이 아니면 `--trust-local` 거부.

### [P3] C-7 · 무인증 /api/health가 운영·에이전트 메타 누출
`web/server.py:472-491`
- **Impact**: 토큰 없이 `busy`·`viewers`·`agents`(서브에이전트 이름/역할) 반환. 0.0.0.0 바인드서 무인증 LAN 피어가 활동 지문·에이전트 역할 열거.
- **Fix**: 무인증 프로브는 `{"status":"ok"}`만, 리치 필드는 토큰 게이트.

## ② SSRF & 자격증명 유출

### [P1] C-1 · fetch SSRF — 호스트/스킴 필터 없음, 리다이렉트 자동 추종
`tools/fetch.py:97-102` (`allow_redirects=True`) · `161-167`
- **Impact**: `127.0.0.1`·`169.254.169.254`(클라우드 메타데이터)·RFC-1918 차단 전무. 방문 페이지의 프롬프트 인젝션이 에이전트로 하여금 메타데이터 엔드포인트를 fetch→본문이 컨텍스트로 유입→IAM 자격증명 절취. confine/confirm 게이트가 **제로**인 유일 변이 경로.
- **Fix**: 호스트 해석 후 loopback/link-local/private/reserved면 거부(`ipaddress`). `allow_redirects=False` 후 매 홉 재검증. 스킴을 http/https로 제한.

### [P1] C-2 · fetch 본문 무제한 메모리 적재(DoS / 압축폭탄)
`tools/fetch.py:97-119`
- **Impact**: `requests.get`(비스트림) 후 `resp.text[:MAX]` — 캡이 *디코드 후* 적용. 수 GB 본문·gzip 폭탄(자동 해제)으로 OOM. C-1과 동일 인젝션 경로.
- **Fix**: `stream=True` + Content-Length/누적 바이트 캡, 해제 바이트 상한.

### [P3] L-15 · 10MB 프로브 본문을 임의 엔드포인트로 POST
`providers/capabilities.py:94, 480`
- **Impact**: 미지 OpenAI-호환 엔드포인트(호스티드 API 포함)에 `"word "×2,000,000`을 물질화·전송. `_last_was_runtime_detected`는 비동기화 모듈 전역.
- **Fix**: 프로브 크기 축소·대상 제한, 전역 상태를 결과 provenance로 반환.

## ③ 경로 격리 & 심볼릭 링크

### [P2] C-3 · 틸드(~) 격리 우회 — 홈 디렉토리 쓰기를 "내부"로 오판(실증)
`tools/_confine.py:53-63` (`resolve_within`) vs `78-95` (`_path_candidate`)
- **Impact**: `_path_candidate`는 `~/…`를 게이트하려 추출하지만 `resolve_within`의 `Path().resolve()`는 `~`를 확장 안 함 → `<ws>/~/exfil`로 판정돼 inside=True인데 셸은 `$HOME`으로 확장. `cp .env ~/exfil`·`> ~/.ssh/authorized_keys`가 무프롬프트.
- **Fix**: `Path(os.path.expanduser(path))`로 resolve 전 확장 + `~/x`/`$HOME/x` 회귀 테스트. 추출기와 해석기가 단일 정규화 단계 공유.

### [P2] C-6 · zip 다운로드가 심링크 추종 — 워크스페이스 밖 파일 유출
`web/server.py:851-897` (`_build_zip`)
- **Impact**: `rglob`+`is_file()`가 타깃이 밖인 심링크를 따라감. `relative_to`는 *미해석* 링크 경로라 성공 → 아카이브에 `/etc/passwd`·`~/.ssh/id_rsa` 포함.
- **Fix**: `if f.is_symlink(): continue` 또는 `f.resolve()` 재검증. `_dir_size`에도 동일.

### [P3] S-8b · sidecar 컨테인먼트 검사가 prefix 기반
`render/web.py:1036-1039`
- **Impact**: `str(target).startswith(str(session_dir))`는 형제 `…/sess-evil`을 세션 `…/sess`로 수용. 방어심층용이나 주석과 실제 불일치.
- **Fix**: `target.is_relative_to(session_dir.resolve())`(3.10+).

### [P3] C-10 · workspace_tree 심링크 사이클 DoS
`web/server.py:815-823` (`_dir_size`, `rglob`)
- **Impact**: 워크스페이스 내부 심링크 사이클이 walk를 무한/고비용화 → executor 스레드 hang.
- **Fix**: walk 시 심링크 skip.

## ④ 컨텍스트·히스토리 정합성

### [P1] L-1 · overflow 오탐지가 히스토리를 되돌릴 수 없게 파쇄 — ✅ RESOLVED (v8.6.1)
> typed `ContextOverflowError`(경계 raise) + `classify_overflow` HTTP 상태 게이트로 해결. 상세: `docs/L1-overflow-typed-error-plan.md`.
`context/overflow.py:29-33` · `loop/llm.py:174-176` (`except Exception`)
- **Impact**: bare `context window`·`input.*too long` 패턴을 *임의* 예외의 `str(e)`에 매칭. 그 문구를 담은 설정 오류·프록시 페이지가 `force_fit`을 유발 → FIFO evict + `_dynamic_start_index` 전진 + `compaction.json` 영속화를 최대 5회. resume가 전진된 오프셋을 읽어 손실 **영구**. (조건부 latent: 비-overflow 예외 메시지가 그 문구 포함 + ctx 존재 + retries<5)
- **Fix**: provider 경계(`raise_for_status_with_body`)에서 status+body를 알 때 typed `ContextOverflowError(actual, limit)`를 HTTP 400+엄격 패턴에만 raise. 루프는 정규식 대신 타입을 catch. → 근본 시임 L-25.

### [P1] L-2 · xml_fc의 스트리밍 degeneration 조기중단이 dead
`providers/http.py:444-449` (`"#" in ev.text` 게이트)
- **Impact**: 공유 스켈레톤에 json_fc 전용 휴리스틱(마크다운 `#`)이 하드코딩. xml_fc 폭주 형태(반복 `<tool_call>`)엔 `#`가 없어 매번 전체 출력예산(256K 모델서 64K)을 소진.
- **Fix**: 트리거를 wire format이 소유(`degeneration_gate_chars` 속성) 또는 청크 카운트로 스로틀.

### [P2] L-3 · 기본 wire format에서 truncation 가드가 dead → 조작된 edit 실행
`wire_formats/json_fc.py:682-691` vs `loop/dispatch.py:781`
- **Impact**: `_sanitize_truncated_edit`는 `op.truncated`에 반응하지만 json_fc의 `_ops()`는 이를 세팅 안 함(기본 False). `close_unbalanced`/따옴표 수리로 닫힌 edit이 조작된 마지막 줄로 **경고 없이 실행**. xml_fc는 정상 세팅.
- **Fix**: `_ops`에서 `Op(…, truncated=repaired)`. → 근본 시임 L-24.

### [P2] L-4 · fold 후 _dynamic_start_index 어긋남 → resume 상태 드리프트
`context/manager.py:735-783, 627-653`
- **Impact**: `fold_resolved_interventions`는 캐시에서 레코드를 빼지만 history엔 남음. evict/compact는 *캐시* 카운트로 오프셋 전진 → resume가 evict된 레코드·개입을 되살리고 요약이 이미 덮은 내용 재투입.
- **Fix**: 각 캐시 레코드에 history 라인 인덱스 스탬프, 카운터가 아닌 레코드 인덱스로 전진.

### [P2] L-5 · flow-1 전처리가 try 밖 → 미처리 예외가 런을 죽임
`loop/llm.py:76-90` (try는 `:143`)
- **Impact**: `_save_compaction_json`의 OSError·`extract_file_paths` 버그·렌더러 예외가 raw로 `run()`까지 전파 → 웹 워커 스레드/프로세스 사망, `OnTurnEnd`(안전망) 스킵.
- **Fix**: try 확장 또는 flow-1을 FIFO로 강등하는 자체 가드로 감쌈.

### [P2] L-6 · force_fit 과다 eviction — keep 비율을 압축 후 크기에 적용
`context/manager.py:699-716`
- **Impact**: step1 `_compact()`로 축소 후 `floor = _cache_tokens × (target/actual)`인데 `actual`은 *압축 전* 서버값 → 필요량의 약 2배 버림.
- **Fix**: 압축 전 `_cache_tokens` 스냅샷에서 스케일, 또는 `actual` 비례 재계산.

## ⑤ 동시성 & 프로세스 수명

### [P0] S-1 · _agents 무락 순회 → spawn 레이스가 무관한 에이전트를 오사망
`subagent/agents_live.py:950` (`_save_state`) · 뮤테이터 `:553`/`:899`/`:1042`
- **Impact**: `_save_state()`가 워커 스레드에서 `self._agents.values()`를 락 없이 순회하는 동안 main 스레드가 `spawn` 삽입 → `RuntimeError: dictionary changed size`가 워커의 `except BaseException`으로 전파 → **다른** 에이전트가 죽음·비재생 처리. "orchestrate가 워커 5개 spawn 중 워커1이 회신" = 실사용 부하 패턴. 동일 무락 순회가 `roster_snapshot`·`has_active_work` 등 6곳.
- **Fix**: `_agents`를 guarded state로 — `with self._cv:` 하에 `list(self._agents.values())` 스냅샷 후 순회. 모든 삽입/교체도 동일.

### [P1] S-3 · WebRenderer._pending_thought가 스레드 간 단일 슬롯
`render/web.py:192, 1244, 1254-1265`
- **Impact**: 이벤트 *라우팅*은 per-thread이나 thought/action *페어링*은 공유 필드. 워커 B의 thought가 main의 held thought를 덮음 → 잘못된 추론이 잘못된 카드에 붙거나 유실. base는 provenance용 `_thread_thought`를 이미 스레드 키로 해결.
- **Fix**: `dict[int, str]`로 스레드 id 키잉, 같은 스레드의 action/final이 소비.

### [P2] S-7 · tree-sitter parser 캐시가 락 없이 스레드 공유
`code_index/builder.py:41,81-86` · `tools/code_index.py:261`
- **Impact**: `Parser.parse()`는 단일 인스턴스 동시 사용 비안전. 빌드는 `_BUILD_LOCK`로 직렬화되나 delegate 워커의 `code_index view` 슬라이스 파싱이 락 밖에서 같은 캐시 parser 사용 → UB/세그폴트.
- **Fix**: `threading.local()` parser 캐시 또는 슬라이스 파싱을 락으로 감쌈.

### [P2] S-9 · kill 후 resume가 한 키에 워커 2개를 남길 수 있음
`agents_live.py:826-846` (kill join timeout=2s) · `859-913` (resume)
- **Impact**: 바쁜 워커(턴 경계서만 stop 체크)가 2초 join 생존. kill이 성공 반환하고 모델에 resume 권유 → 구스레드 실행 중이면 두 워커가 `conversation.jsonl`·`reply-N.md` 공유, 구워커 finally가 신인스턴스 스코프 닫음.
- **Fix**: `resume_teammate`는 `worker.is_alive()` 동안 거부/대기. kill 회신은 스레드 종료 확인 전엔 resume 광고 금지.

### [P3] L-cc · ContextManager가 크로스 스레드 공유 중 thread-unsafe
`context/manager.py` (`set_compaction_ratio` · `compact_now`)
- **Impact**: 웹 슬라이더·`/compact`가 서버 스레드, 루프 스레드는 `_cache`/`_nl_cache` 변이. `compact_now`가 in-flight `ensure_within`과 인터리브하면 캐시 재빌드 경합.
- **Fix**: confinement 규칙 문서화, `/compact`를 기존 턴-경계 주입 큐로 라우팅.

## ⑥ 성능 핫패스

### [P2] S-6 · code_index: 매 쿼리 전 레포 재해시 + 매 edit DB 전량 재작성 (최대 레버)
`tools/code_index.py:100-114` · `builder.py:161-178, 380-491`
- **Impact**: `_ensure_index()`가 *모든* 쿼리 모드 전 `build()` 실행 → 클린 증분이어도 전 파일 바이트 read+SHA1 후 SQLite 전량 재삽입. 커널 규모 트리서 `code_index` 호출·`write_file`/`edit_file`마다 수백 MB I/O.

## 🔗 경계 (agent-cli ↔ agent-board) — 두 저장소에 걸친 종속 항목

> 이 섹션은 **양쪽 문서에 공통**. 나머지는 각 저장소 전용.

### A. 보안 노출은 단일 공격면 (완화가 조율돼야 함)
board-proxy는 cli 인스턴스에 **loopback으로 중계**하고, cli는 `--trust-local`로 loopback 요청의 토큰을 스킵한다. 따라서 board의 인증 부재(**B-1**)가 그대로 cli 인스턴스의 노출이 된다. 한쪽만 잠그면 우회 가능:
- board만 loopback 잠금 + cli 인스턴스 포트(50000–60000)가 직접 도달 가능 → board 우회로 cli 직격
- cli만 loopback + board가 `0.0.0.0` → board-proxy가 여전히 중계

→ **C-4·C-5·C-11**(cli)와 **B-1·B-2**(board)는 **함께** 완화해야 온전. 두 저장소 동시 작업.

### B. 경계 계약의 수정이 양쪽 코드를 건드림
- **B-12**(board): board가 cli의 private `_detect_runtime_capabilities`/`list_names`를 import → **fix는 agent-cli가 공개 API를 노출**해야 완결(이 저장소 변경 필요).
- **B-13**(board): board가 cli on-disk 포맷(`status.json`/`web.json`/`history.jsonl`/`session.jsonl`)을 파싱·기록 → 계약 테스트는 실 agent-cli 필요. **cli 측이 이 포맷을 바꾸면 board가 조용히 깨진다** — 세션 파일 스키마 변경 시 board와 협의/버전 범프.
