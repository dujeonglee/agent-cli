# 성능 KPI — 세션 로드(스냅샷 재생)

보드에서 **대화가 쌓인 게시글을 열 때의 체감 로드 시간**을 지표로 관리한다.
v8.42.0 회귀(이벤트당 전체 재렌더 + 카드당 강제 레이아웃 → O(N²))가 재발하지
않도록, **가드(단언)** 와 **KPI(측정·기록)** 를 분리해 운영한다.

## 왜 둘로 나누는가

| | 가드 (TC) | KPI (측정) |
|---|---|---|
| 무엇 | 렌더/스크롤 호출 **횟수** 불변식 | 메인스레드 **블로킹 시간**(ms) |
| 판정 | 단언 — 깨지면 테스트 실패 | 단언 없음 — 표로 기록·추세 관리 |
| 위치 | `tests/browser/test_render_perf.py::TestRenderCoalescingRuntime` | 같은 파일 `TestRenderKpi` |
| 이유 | 하드웨어 무관 → 느린 CI 에서도 안 흔들림 | 절대 임계는 머신 종속 |

**벽시계 시간을 단언하지 않는 이유**: 임계를 낮게 잡으면 느린 CI 에서 오탐이
나고, 높게 잡으면 빠른 머신에서 실제 회귀(수리 전 351ms)도 통과해버린다 —
flaky 하면서 동시에 무력하다. 그래서 **회귀 판정은 횟수 불변식이 맡고**,
시간은 사람이 보는 지표로만 남긴다.

## 가드가 지키는 불변식

스냅샷 240 이벤트를 재생해도:

- `#overview` 전체 재작성(= `ovRender`) ≤ **20회**
- `#messages` 의 `scrollTop` 쓰기(= `scrollToBottom`) ≤ **20회**

정당한 발생량은 "재생이 걸친 프레임 수"뿐이다(실측 **2회 / 1회**). 병합이
풀리면 이벤트당 1회가 되어 **121회 / 240회**로 튄다 — 상한 20 과 6~12배 격차라
판정이 흔들리지 않는다.

함께 단언하는 **기능 계약**(병합이 화면을 망가뜨리지 않았는가):

- 재생된 카드 수 == 방출 이벤트 수 (아무것도 안 그려서 빨라진 게 아님)
- 개요가 **최신** 응답을 반영 (rAF 마지막 1회가 최종 상태를 그림)
- 타임라인이 자동 스크롤로 바닥에 도달 (여유 ≤ 50px)
- 라이브(접속 후 도착) 경로도 동일하게 병합 — 스냅샷만 고치는 반쪽 회귀 방지

> 뮤테이션 검증 완료: v8.41.0 app.js 로 되돌리면 위 가드가 **3/3 실패**한다
> (개요 재작성 121회, 라이브 60회, 자동 스크롤 158px 미달).

정적 소스 핀 `tests/test_web_server.py::TestRenderCoalescing`(직접 호출 부활
금지)과 상호 보완이다 — 정적 핀은 소스 문자열을, 런타임 가드는 실제 호출
횟수를 본다(다른 이름의 호출·병합기 무력화·새 이벤트 훅은 런타임만 잡는다).

## 베이스라인 (동일 하네스, Apple M-series, headless chromium)

턴당 4이벤트(user + observation×2 + final) 스냅샷을 재생한 뒤 측정.

| 스냅샷 이벤트 | 블로킹 (v8.41.0) | 블로킹 (v8.42.0) | 로드→안정 (전 → 후) |
|---|---|---|---|
| 120 | 78ms | **0ms** | 201ms → 163ms |
| 360 | 202ms | **59ms** | 322ms → 167ms |
| 600 | 351ms | **87ms** | 472ms → 215ms |

절대값은 하네스·머신에 종속되므로 **같은 하네스 안에서만** 비교한다. (실세션
프로파일링에서는 마크다운 본문이 더 무거워 888이벤트 기준 1012ms → 277ms 였다.)

## 실행

```bash
# 회귀 가드 (릴리스 전 필수 — 브라우저 스위트에 포함)
AGENT_CLI_BROWSER_TESTS=1 pytest tests/browser/

# KPI 측정 (프런트 렌더 경로를 건드린 릴리스에서 수행)
AGENT_CLI_BROWSER_TESTS=1 AGENT_CLI_PERF_KPI=1 pytest tests/browser/test_render_perf.py -s
#   → stdout 표 + perf-kpi.json (run 산출물, gitignore)
```

## 회귀 판정 기준

1. **가드 실패** → 회귀. 병합 경로가 풀렸거나 새 이벤트 훅이 직접 렌더를 부른다.
2. 가드는 통과인데 **KPI 블로킹이 같은 머신에서 2배 이상 증가** → 다른 원인의
   성능 저하(카드 DOM 비용·마크다운·새 렌더 경로). 프로파일링으로 원인 특정 후
   이 문서의 베이스라인 표를 갱신한다.

## 알려진 잔여 (다음 후보)

블로킹의 남은 대부분은 **카드 DOM 생성 자체**다. 더 줄이려면 전문(드로어)
타임라인의 가상화/지연 렌더가 필요하다 — 현재 수치(600이벤트 87ms)로는
우선순위가 낮아 보류.
