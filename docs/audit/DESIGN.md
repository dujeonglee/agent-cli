# 중복 제거와 추상화 — 감사와 그 결론

> 상태: **1~3단계 완료 · 4단계 일부 · §7.3 해소** (v9.8.0) · 2026-09-19
> 리포트: https://claude.ai/code/artifact/a2cdb009-bcc2-4b56-844b-6af9886ef5a5
> 조사: 읽기전용 에이전트 4대 (frontend · renderer · object-model · ux)

## 1. 왜 조사했나

사용자 요청: *"전반적으로 코드 그리고 UI/UX 에서 중복을 제거하고 싶다. 같은
패턴이 여러 군데 보이면 헬퍼로, render·LLM 추상화 표면에 추가할 것이 없을지,
렌더링 객체를 추상화해 확장성을 높일 수 없을지."*

네 갈래로 나눠 병렬 조사했고, 각 주장에 `file:line` 증거와 개수를 요구했다.
직전 이틀간 내(구현자) 판단이 두 번 "그럴듯한데 틀렸"기 때문에, 근거 없는
제안을 받지 않으려는 장치였다.

## 2. 조사 결과 — 결함들이 한 문장으로 모였다

서로 다른 네 조사가 같은 얼굴을 찾았다:

> **코드는 있고, 테스트는 초록이고, 화면에는 아무것도 없다.**

열한 건이 이 부류였고, 세 갈래로 갈린다:

| 갈래 | 사례 |
|---|---|
| CSS 가 JS 를 안 받음 | `.tv-nav-hl`(점프 하이라이트 무동작) · `.hd-chip[hidden]`(빈 칩 상시 노출) · `.args`(미지 도구 JSON 이 카드를 뚫음) |
| 이벤트가 버려짐 | `status`(호출 10곳, 리스너 0) · `thinking` · `model_detected`/`model_loaded` |
| 구분은 있는데 안 나름 | 깨우기 말풍선 · 채널 누수 3건 · confinement 위반 미고지 |
| 절반만 적용됨 | main confirm 중복(CLI 엔 게이트가 있는데 웹엔 없음) · `stream_reset` 웹 무동작 |

**개별 버그보다 이 패턴이 본체다.** 그리고 패턴의 원인이 도구의 부재였다 —
조사 에이전트의 말이 정확했다: *"스크린샷으로는 `white-space: pre` 를 잡을 수
없다. 규칙을 읽어야 하는데 **그 규칙이 존재하지 않아서 읽을 수가 없었다**.
주의력 문제가 아니라 도구 문제다."*

## 3. 범용 추상화는 — 하지 않는다

사용자 질문("렌더링 객체를 추상화해 확장성을")에 대한 답. **두 에이전트가
독립적으로, 한쪽은 정성·한쪽은 정량으로 접근해 같은 결론**에 도달했다.

```
− 85줄   descriptor 테이블이 지워줄 것 (카드 껍데기 10개 · card-sys 7개 · classify)
+ 200줄  descriptor 18항목 × 7필드(130) + 제네릭 드라이버(70)
± 0      어느 쪽이든 안 줄어드는 per-type 본문 포맷팅 ≈ 548줄
─────────
+ 115줄  순증 + 간접층 하나. 미래 아이템당 ~20줄 절약 → 손익분기 ~6종
```

관측된 신규 아이템 추가 속도가 분기당 ~2종이므로 손익분기는 **수년** 뒤다.
CLAUDE.md §7(불필요한 추상화 금지)에 정면으로 걸린다.

**결정적인 관찰 셋:**

1. **값이 나는 통합은 이미 했다.** v9.4.0 ③ 의 `makeRow()`(4칸 리듬)를 다섯
   아이템 타입이 공유한다. 지금 본문 구성이 안 겹치는 이유는 **겹치는 부분이
   이미 뽑혀 나갔기 때문**이고, 그게 더 뽑지 말아야 할 가장 강한 근거다.
2. **두 구현 바닥.** `base.Renderer` 에 `MinimalRenderer`(터미널)와
   `WebRenderer`(SSE) 둘이 있어, 새 아이템은 ABC + 양쪽 구현이 **무조건**
   필요하다. 프론트 descriptor 로는 못 내리는 바닥이라 절감 상한이 낮다.
3. **확장성 전제가 약하다.** "MCP 도구 호출"은 새 아이템 타입이 **필요 없다** —
   MCP 는 이미 `action()`/`observation()` 을 탄다. 가장 그럴듯한 후보가
   필요없다는 것이 이음매가 이미 제자리에 있다는 증거다.

### 대신 한 것 — `finishCard(el, ev, channel)`

13개 렌더러가 진짜로 공유하는 건 본문 구성이 아니라 **꼬리 배관**(시각 도장 ·
채널 귀속 · 스크롤)이고, 최근 누수가 **전부 거기서** 났다.

인자는 **이벤트 페이로드 통째**다. 추출한 id 를 받으면 `undefined` 가 조용히
통과하지만(실제로 `transcript_truncated` 가 그랬다), 페이로드를 받으면 귀속
누락이 "필드를 잊었다"가 아니라 **"인자를 안 넘겼다"** 가 된다.

## 4. 아무도 모델링하지 않던 축 — 지속성은 세 단계

조사의 **가장 값어치 있는 발견**.

```
① 라이브 팬아웃        모든 이벤트
② 재접속 리플레이      persistent=True → _event_buffer
③ --resume 리플레이    ContextManager 가 history.jsonl 에 썼는가
```

**③은 ②에서 파생되지 않는다.** `persistent=` 는 `_emit` 의 파라미터인데 ③은
**렌더러가 보지도 못하는** `loop/core.py` 의 창발적 성질이다. 그래서
`_replay_record` 는 다섯 필드 어휘(`role` · `tool` 유무 · `author` ·
`author_is_user` · `ops`)로 표시 타입을 **재구성**하고, 그 다섯으로 표현 안
되는 구분은 전부 잃는다.

부류 4건이었고, **초록 두 줄이 진짜 증거**였다:

| 아이템 | resume 후 | |
|---|---|---|
| 깨우기 | 말풍선으로 부활 | v9.8.0 수리 |
| 거부된 응답 | 원문이 사라짐 | **§7.3 — 반대 방향으로 해소** |
| 관찰 | 일치 — `removeprefix("Observation: ")` 덕 | 일회성 shim |
| 왕래 | 일치 — `lastFinalByChannel` 덕 | 일회성 shim |

초록 둘은 설계가 아니라 **각각 다른 파일에 박은 일회성 shim** 이다. 둘 다
어렵게 발견해 때운 것이고, **불변식을 선언하는 곳이 없어서** 깨우기가
빠져나갔다.

→ `WebRenderer.REPLAY_CONTRACT`(재생 7종, 어떤 레코드 모양으로) +
`REPLAY_LIVE_ONLY`(의도적 비재생 4종, 이유와 함께). 테스트가 실제 방출과
대조해 **"영속인데 선언이 없다"** 를 잡는다. 무엇이 맞는지는 판단할 수 없지만
**판단을 강제**할 수는 있다.

## 5. 정적 검사 — 개별 수정보다 값이 크다

열한 건 중 여섯을 정적으로 막는다. 전부 `tests/test_web_server.py`.

| 가드 | 무엇 | 허용목록 |
|---|---|---|
| `test_every_js_class_has_a_css_rule` | JS 가 붙이는 클래스에 CSS 규칙이 있는가 | 7개, 전부 "규칙이 없어도 맞는" 이유 명시 |
| `test_every_emitted_event_has_a_listener` | `_emit` 이벤트에 리스너가 있는가 | `cli_only` 8개, 이유 명시 |
| `test_append_to_timeline_always_carries_a_scope` | 루트 append 가 스코프를 나르는가 | — |

**정적 검사가 두 번 일했다:**

1. 넣자마자 `transcript_truncated` 의 스코프 누락을 잡았다 — 조사가 "이 부류의
   마지막 미수정 사례"로 지목한 바로 그 줄.
2. 4단계에서 중계 5개를 표로 접었더니(~20줄 절약) 이벤트 가드가 실패했다.
   `es.addEventListener("리터럴"` 패턴이 깨져 **가드가 그 리스너들을 못 보게**
   된다. 되돌렸다 — **20줄보다 가드가 값지다.**

### `[hidden]` — 탐지 대신 제거 (v9.8.0)

`hidden` 은 HTML 속성이고 브라우저는 그걸 **UA 시트의 규칙 하나**
(`[hidden]{display:none}`, 특정도 0,1,0)로 구현한다. 그런데 **작성자 시트가 UA
시트를 이기므로**, 우리가 `display` 를 선언한 요소는 `el.hidden = true` 를 걸어도
안 숨는다. 속성은 붙는데 화면엔 그대로다.

이 사고가 **네 번** 났다:

| | 증상 |
|---|---|
| `#stall-pop` | 팝업이 항상 열려 있음 |
| `.card-user` | 채널 필터가 사용자 말풍선에 안 먹음 |
| `.hd-chip` | 빈 칩 2개가 첫 페인트부터 노출 |
| `#ov-channels` | 탭 1개짜리 탭바가 상시 표시 |

매번 **그 셀렉터에만** 가드(`#foo[hidden]{display:none}`)를 붙였다. 그건 다음
요소를 기다리는 것이다. 다섯 번째에 가드를 또 붙이는 대신, **정적 검사를
만드는 것도 아니라**, 부류 자체를 없앴다:

```css
[hidden] { display: none !important; }
```

흩어져 있던 개별 가드 **15개를 지웠다** — 이 한 줄이 전부를 덮는다.
`:not([hidden])` 을 쓰는 규칙들은 hidden 이 아닐 때만 매칭되므로 충돌하지 않는다.

**탐지보다 제거가 낫다**는 게 요점이다. 정적 검사는 "빠뜨렸다"를 알려줄 뿐이지만
전역 규칙은 빠뜨릴 수가 없게 만든다. (검증: 이 한 줄을 지우면 브라우저 TC 6개가
동시에 깨진다 — 채널 필터·중첩 접기·노브 팝업·MCP 칩.)

### 정적 검사가 거는 제약 (지키지 않으면 조용히 무력해진다)

- **SSE 리스너는 이벤트 이름을 리터럴로** 쓴다. 표로 접지 않는다.
- 스타일 없는 클래스를 추가하려면 **왜 없어도 되는지**를 허용목록에 적는다.
  빈 규칙(`.foo { }`)으로 가드를 달래는 것은 거짓 위안이다.
- 새 영속 이벤트는 `REPLAY_CONTRACT` 또는 `REPLAY_LIVE_ONLY` 에 등록한다.
- 새 카드 클래스는 `classify()`/`CARD_KINDS` 에 등록한다 — 안 하면 export 에서
  조용히 빠진다(`card-msg`·`card-sys` 가 그랬다).

## 6. `status` — 왜 리스너를 붙였나

처음엔 "`status` 는 CLI 모양 계약이니 웹에선 no-op 으로 만들고 전용 동사를
강제하자"고 판단했다. **사용자 반문("webui 엔 도움이 안 되나?")에 재검토했고,
틀렸다.** 다섯으로 갈라 보니 셋은 웹에 있어야 한다:

| 종류 | 웹에 필요 | 처리 |
|---|---|---|
| 런 종료 사유 (Max turns · action loop) | **필수** | `render_run_ended` → `turn_error`(영속) |
| 재시도·열화 (HTTP ×3 · 컨텍스트 오버플로) | **필요** | `status` 리스너 → 휘발 `card-sys` |
| 부팅 고지 (에이전트 복원·auto-spawn) | **필요** | 동일 |
| 모델 탐지 프로브 | **불가능** — 부트스트랩이 uvicorn 보다 먼저 돈다 | 그대로 |
| `Running agent: X…` | 불필요 — 스코프 카드가 중복 | 그대로 |

내가 반대했던 근거("제네릭으로 받으면 넷을 똑같이 그려 최소 한 방향은 틀린다")
는 **하나만** 틀렸다. 휘발 한 줄이 이 부류의 올바른 기본값이고, 대화 기록에
남아야 하는 것(런 종료 사유)만 따로 보내면 된다.

두 번째 반대 근거("다음 사람이 `status` 를 부르면 설계 없이 회색 줄로
떨어진다")도 무효였다 — 그게 **올바른 기본값**이다. 이 반론은 기본값이
*안 보임*일 때만 성립했다.

**남은 성질**: `status` 는 여전히 "어디에 어떻게 그려질지 모르는 채로 보내는"
동사다. 지금은 기본값이 합리적이라 괜찮지만, 제자리 갱신이나 채널 귀속이
필요한 알림이 나오면 그때 전용 동사로 올린다 — `stream_stall`·`compaction` 이
정확히 그렇게 태어났고, 그건 실패가 아니라 **정상적인 승격 경로**다.

## 7. 남은 것

### 7.1 구조 — 셋이 결합돼 있다

| 항목 | 절감 | 위험 |
|---|---|---|
| 노브 IIFE 6개 통합 (`apiJSON` + `knob({wrap,endpoint,event,apply})`) | ~120줄 | 중 |
| 드로어 3개 (`drawer($el,$backdrop,{onOpen})`) | ~50줄 | 중저 |
| 공용 prelude (`el`·`escapeHtml`·`fmtTok`·클립보드·blob 다운로드) | ~70줄 | 낮음 |

**왜 미뤘나**: 셋은 독립 항목이 아니다. 각 IIFE 가 별도 스코프라 `apiJSON`
하나를 공유하려면 **최상위 네임스페이스부터 도입**해야 하고, 그건 *"메인 렌더
루프 무수정"* 이라는 IIFE 격리 설계(ARCHITECTURE 가 반복해 근거로 드는 성질)를
건드리는 변경이다. 동작 변화가 0 인 리팩터링이라 급하지 않다.

**착수 시 주의**: `makeRow`·`collectEntries` 는 **이름만 같고 다른 함수**다.
hoist 하면 안 된다. 노브의 `apply()` 본문도 진짜로 다르다(stall 은 두 축 +
파생 줄 + "포커스된 입력 건드리지 않기" 가드, mcp 는 목록 렌더, confirm-mode 는
wrap 이 없다) — 껍데기만 접고 본문은 그대로 둔다.

### 7.2 판단이 필요한 UI/UX 중복

조사가 "제거 시 잃는 것"까지 적어 왔다. **아직 결정하지 않았다.**

| 중복 | 제안 | 잃는 것 |
|---|---|---|
| 에이전트 질문이 **4곳** (칩 dot + 칩 ❓ + 트레이 + 왕래 줄) | ❓ 배지만 버림 — dot 과 **같은 칩 안에서** 같은 사실을 두 기호로 | dot 색(시안)의 의미를 학습해야 함 |
| 💭 사고 토큰이 헤더와 대화에 동시에 같은 숫자 | 헤더 배지 버림 | 스크롤을 올려 과거를 읽는 동안 카운터가 안 보임 |
| main confirm 이 바로 위 두 줄을 반복 | 버림 — **CLI 엔 이미 게이트가 있다**(`base.py:186` `if not meta["agent"]: return ""`), 웹에만 없음 | 없음 |
| `📨` 와 `🤝` 가 같은 사건을 다른 언어로 | 조건부 — `agent_wake` 가 뒤따르면 `📨` 생략 | main 이 busy 면 `📨` 가 유일한 도착 신호 |
| 🧠 칩이 "켜진 채로 죽어 있음" (+ 이 칩만 노출 가드 누락) | 배지를 `auto` 대신 `미지원` 으로, 가드 추가 | 숨기면 "이 모델은 사고 미지원"을 알 길이 없음 |
| 노브 4개가 공장 기본값 상시 전시 | 부분 — 🔌 칩 판례(*"0/0 은 정보가 아니라 소음"*). 👥 는 에이전트 0명이면 숨겨도 안전 | 발견 가능성 |
| 탭 1개짜리 탭바 (`:empty` 가 **절대 발동 안 함**) | roster 0명이면 바 전체 숨김 | 에이전트 생성 시 레이아웃 점프 |
| `user_message.author` 를 아무도 안 읽음 | **지우지 말고 쓸 것** — 말풍선 `[닉]:` 접두를 2인 이상일 때만 그리는 재료 | — |

### 7.3 ~~미검토~~ — 해소됨 (v9.8.0)

**거부된 응답의 resume 괴리**: 라이브는 거부된 원문 + `⚠ 사유` 를 보여주는데
resume 후엔 사라졌다(history 엔 정제된 assistant 레코드와 개입 관찰만 있다).

**해법은 반대 방향이었다** — 사용자 결정: *"거부한 거 자체를 보여주지 말자.
상용 모듈은 다 이런 것 같고, 우리 어차피 라이브 스트리밍도 안 한다. 그냥 더
오래 생각하는구나 정도로 아는 거지. 대신 더 이상 재시도 안 할 경우엔 마지막
실패 메시지를 보여주고."*

resume 을 라이브에 맞추는 대신 **라이브를 resume 에 맞췄다.** 근거:

- 거부된 응답은 **모델의 작업이 아니라 하네스의 재시도 기계**다. DESIGN 의
  투명성 대상("대화·셸 수행·reasoning")과 범주가 다르고, 사용자가 할 수 있는
  일도 없다(모델의 형식 준수는 고칠 수 없다).
- 괴리가 **구조적으로** 사라진다 — history 에 없는 것을 라이브도 안 그리면
  둘이 어긋날 자리가 없다.
- 개입 관찰도 같이 숨긴다. 하나만 숨기면 **맥락 없는 빨간 줄**(`✗ 결과`)만
  남아 더 나쁘다.

**대신 남긴 것 둘:**

1. **생성 중 줄의 재시도 카운터** — `● 생성 중 · 50 tokens · ↻ 재시도 3`.
   "그냥 느린 것"과 "형식 거부로 맴도는 것"은 구별돼야 한다. 형식 붕괴가 잦은
   로컬 모델에선 실제로 다른 상황이고, 후자면 `--verbose` 로 넘어갈 신호다.
   (`retry_tick`, `persistent=False` — 재접속 때 되살리면 옛 시도분이 카운터에
   더해진다. `stream_tick` 과 같은 성질.)
2. **하드페일은 영속으로** — `render_run_ended` → `turn_error`. 1단계에서 이미
   옮겨둔 경로가 그대로 이 요구를 만족했다.

**잃은 것 (기록)**: 형식 문제를 **화면에서** 진단할 수 없다. 남는 경로는
`--verbose` 디버그 로그와 history 의 정제된 assistant 레코드다. 재시도 카운터가
"형식 문제가 있다"는 신호는 주므로 거기서 `--verbose` 로 넘어가는 흐름이다.

## 8. 남길 교훈

1. **"소스 멀쩡 + 테스트 초록 + 화면 공백"은 부류다.** 개별로 고치면 다시 온다.
   정적 가드가 개별 수정보다 값이 크다.
2. **테스트는 기하/가시성을 봐야 한다.** `hidden` 속성이 붙었는지가 아니라
   실제로 안 보이는지, 클래스가 붙었는지가 아니라 애니메이션이 도는지.
   속성 검사는 이 부류를 그대로 통과시킨다(실제로 통과하고 있었다).
3. **판단을 코드에 적는다.** CLI 의 confirm 게이트는 *"main already prints its
   thought/action inline right above the prompt"* 라고 **이유까지** 적혀 있어
   살아남았다. 같은 판단이 웹엔 없어서 중복이 남았다 — 적히지 않은 판단은
   절반만 적용된다.
4. **일회성 수리를 세 번 하면 일반 경로를 닫는다.** `agent_mail_hint`(1회) →
   `stream_stall`(2회) → `status` 리스너(3회). 세 번째에야 가드를 만들었다.
5. **추상화는 "이미 뽑았는가"를 먼저 본다.** 본문 구성이 안 겹치는 것이
   더 뽑을 게 없다는 신호일 수 있다.
