# 신규성 평가, 연구 질문, 평가 방법론 제안

> 작성일: 2026-08-05. 근거: `01`~`05` 문서 전체. 대상 독자: 논문 기획자(저자).

## 1. 학술적 신규성(Novelty) 평가

### 1.1 판정: **신규성 있음 — 단, 프레이밍 조건부**

"여러 인간이 하나의 자율 AI 코딩 에이전트 세션을 동기적으로 공유"하는 주제를 정면으로 다룬 학술 논문은 2026년 8월 기준 존재하지 않는다(04 §6). 교집합 **{동기적 공유 세션} × {전문 코딩} × {다중 인간} × {자율 에이전트(파일 쓰기·명령 실행)}** 는 비어 있다.

다만 세 개의 근접물이 있어, 이들과의 차별화가 논문의 생사를 가른다:

| 근접물 | 무엇인가 | 차별화 논거 |
|---|---|---|
| **Daryanto et al. 2026** (arXiv 2601.12134) — 2인간+1AI 삼자 프로그래밍 실험 | 구도가 가장 유사한 유일한 실증 연구 | ① 교육/협업학습 맥락 ② 제안 기반 어시스턴트(자율 에이전트 아님) ③ 단발 실험실 과제 ④ 종속변수가 학습·사회적 실재감 ⑤ 세션 지속성·상태 문제 미취급 (04 §6-f) — **반드시 인용하고 명시적으로 구별할 것** |
| **Lehmann et al., CHI 2026** — 다중 사용자+AI 협업 문서 편집 | 도메인만 다른 동형 문제 | 코드는 실행 가능·부작용 비가역·테스트라는 객관 신호·리포지토리라는 공유 상태를 가짐 — 문서 편집 결론이 이식되지 않는 이유를 논증 (04 §2) |
| **GitHub Next "Ace"** — 멀티플레이어 에이전트 워크스페이스 (산업 프로토타입) | "코딩 에이전트는 single-player로 설계됐다"는 문제 정의를 산업계가 공식화 | 학술 논문 아님. "설계는 앞서가나 경험적·이론적 이해가 부재"라는 구도로 오히려 motivation 강화에 활용 (04 §6-a) |

### 1.2 신규성의 세 층위

1. **시스템 신규성 (강함)**: Coagora의 "병렬 추론 + 직렬 부수효과" 계약은 상용·연구 시스템 어디에도 없는 조합이다. CopilotKit OpenTag(스레드당 1 run 강제, 409 거부)가 정반대 계약의 상용 실시례로 존재해 teaching-away 논거까지 갖췄다(01 §5). 계층 락(호환성 행렬), per-user 공정 큐, 스냅샷 읽기+원자 커밋의 공유 컨텍스트 정합은 각각 독립된 기술 기여로 서술 가능하다.
2. **실증 신규성 (강함)**: TTFT~L 기울기 0 (n=180), 락 ablation 위반률 74%→0%, "거절+재시도는 직렬보다 나쁘다"(기울기 1.010) — 모두 원자료가 커밋된 재현 가능한 실측이다(01 §6.1). 다중 인간 세션의 공개 상호작용 데이터가 전무하다는 지적(Wang et al., 04 §5)과 결합하면 데이터셋 공개 자체가 기여가 된다.
3. **이론 신규성 (기회)**: CSCW 고전의 다자-에이전트 확장 — **비대칭 grounding**(A-B-Agent 삼자에서 common ground 불균형)과 **다자 제어권 중재**(누가 승인/중단/되돌리기 권한을 갖는가)는 Clark & Brennan, Horvitz가 다루지 않은 명백한 격차다(04 §3, §7.3–7.4). 이 두 개념을 정식화하면 시스템 논문을 넘어 이론 기여가 된다.

### 1.3 위험 요소 (심사 반론 예상)

- **"Ace가 이미 있다"** → Ace는 미평가 프로토타입. 본 연구는 동시성 계약의 명시적 설계 공간 + 실측 + (사용자 연구 시) 경험적 이해를 제공. 오히려 산업 수요의 증거로 인용.
- **"Daryanto가 이미 했다"** → §1.1 표의 5개 논거. 특히 "제안 기반 vs 자율 에이전트" 구별이 핵심 — 자율 에이전트는 공유 상태를 비가역적으로 바꾸므로 조정 문제의 성격이 다르다.
- **"시스템 논문인데 사용자 평가가 없다"** → §4의 방법론으로 대비. 시스템+실측만으로 갈 경우 venue를 시스템 트랙(ICSE/FSE/UIST)으로 조준.
- **"단일 인스턴스, PoC 격리"** → 한계 절에 정직 기재(이미 코드 문서화 문화가 이를 지원, 01 §7). 연구 프로토타입 수준으로는 표준적.

### 1.4 논문 제출 가능성 종합

**제출 가능하다.** 권장 전략은 2단계:
- **1차 (시스템 + 실측)**: Coagora 중심. "다중 사용자 코딩 에이전트 세션의 동시성 계약" — 설계 공간 분류학 + 병렬 추론/직렬 부수효과 시스템 + 벤치마크. 적합 venue: **UIST**(인터랙티브 시스템), **ICSE/FSE**(도구·실증), CHI(시스템+파일럿 스터디 보강 시).
- **2차 (사용자 연구)**: 비대칭 grounding·제어권 중재·awareness를 측정하는 실험/현장 연구. 적합 venue: **CSCW**, **CHI**. 1차의 시스템이 연구 플랫폼이 된다.

## 2. 핵심 연구 질문 (RQ) 제안

### 논문 1 (시스템) 용

- **RQ1 (설계 공간)**: 다중 사용자가 하나의 코딩 에이전트 세션을 공유할 때 가능한 동시성 계약(거부 / 직렬 / 병렬+직렬 부수효과)은 응답성과 산출물 무결성에 어떤 트레이드오프를 만드는가?
  - 가설·근거: TTFT 기울기 1.000 / 1.010 / 0.000 실측(01 §1.2), 락 ablation 74%→0%.
- **RQ2 (부수효과 직렬화의 입도)**: 직렬화 경계를 샌드박스 단위에서 충돌 단위(경로별 파일 락, 셸 배타)로 좁히면 어떤 조건에서 병렬 이점이 보존/붕괴되는가?
  - 근거: E2-B — 전원 파일 수정 시 1.07×로 붕괴 (한계의 정직한 정량화).
- **RQ3 (공유 컨텍스트 정합)**: 단일 공유 대화 히스토리 위에서 병렬 턴을 돌릴 때 LLM 프로토콜 정합(툴콜 짝 맞춤)과 턴 간 간섭을 어떻게 보장하는가? (스냅샷 읽기 + 원자 커밋 메커니즘의 정식화)

### 논문 2 (사용자 연구) 용

- **RQ4 (비대칭 grounding)**: 진행 중인 인간-에이전트 세션에 나중에 참여한 사용자는 어떤 grounding 격차를 겪으며, 이벤트 재생·요약·귀속 표시 중 무엇이 격차를 줄이는가?
- **RQ5 (다자 제어권 중재)**: 여러 사용자가 동시에 지시·제동 권한을 가질 때 turn-taking과 충돌은 어떻게 발생하고, per-user 게이트·턴 단위 인터럽트 같은 메커니즘은 이를 어떻게 바꾸는가? (SWE-chat의 "39% 제동"의 다자 버전)
- **RQ6 (동료 가시성 효과)**: Daryanto의 peer accountability 효과(동료가 보면 AI 산출물을 더 검증한다)가 자율 에이전트의 속도·범위에서도 유지되는가, 아니면 무너지는가?
- **RQ7 (조율 비용 이전)**: 공동 세션은 메신저 방식의 조율 부채를 흡수하는가, 새 형태의 articulation work(턴 협상, 스티어링 타이밍)로 이전시키는가?

## 3. 기술적·이론적 차별화 요소 (논문에서 강조할 것)

1. **동시성 계약의 분류학** — 상태 위치 × 동시성 계약 × 귀속 단위 × 개입 지점의 4축 설계 공간(05 §4.1)에 기존 5개 상용 도구 + OpenTag + Ace + 두 시스템을 배치. 서베이·시스템 양쪽에서 인용될 수 있는 기여.
2. **"병렬 추론 + 직렬 부수효과"의 정식화** — 계약 명제, 호환성 행렬, 공정성(엄격 FIFO, per-user 1활성턴), 안전측 폴백을 형식적으로 기술. OpenTag 대비 teaching-away.
3. **턴 단위 1:1 귀속** — PR 단위 귀속(메신저)과 대비되는 `replyToId` 메커니즘. 다중 화자 트랜스크립트(agent-cli `author` 라벨)와 함께 "누가 에이전트에게 무엇을 시켰나"의 감사 가능성을 제공. 근사 한계(동시 모드 tool 귀속)는 명시.
4. **비대칭 grounding / 다자 제어권 중재의 개념화** — CSCW 고전(Clark & Brennan; Horvitz; Gutwin & Greenberg)의 명시적 확장으로 포지셔닝. "이론적 앵커로 가장 안전한 조합"(04 §8).
5. **재현 가능성 체계** — 결정적 모의 LLM(STUB_MODE), 커밋된 원자료, 실측 상수에서 결정적으로 생성되는 시각 자료. 아티팩트 평가(artifact evaluation) 배지 노릴 수 있는 수준.
6. (보조) **agent-cli의 공유 워커 + 통합 메시지 버스** — 다중 인간과 다중 에이전트가 같은 조정 구조(InputQueue) 위에서 도는 사례로, N×M 조정 문제의 확장 논의에 활용(03 §7.1–7.2).

## 4. 실증 평가 방법론 제안

### 4.1 시스템 벤치마크 (논문 1 — 이미 대부분 존재)

| 실험 | 내용 | 상태 |
|---|---|---|
| E2/E2-B 확장 | 3계약 × 작업 길이 L × 워크로드 혼합비(추론 중심↔파일 수정 중심)의 TTFT/처리량 그리드. 붕괴 지점(1.07×)을 혼합비 함수로 매핑 | 하네스 존재(`backend/bench/e2-hol.mjs`), 혼합비 축만 추가 |
| E1 확장 | 락 입도(sandbox / 충돌 단위 / 없음) 3수준 ablation × 충돌 패턴(동일 파일/동일 디렉토리/삭제 경합) | 하네스 존재, `LOCK_SCOPE` 스위치 활용 |
| 확장성 | 동시 사용자 수 2→8, cap 값 민감도 | mockLlm으로 저비용 실행 가능 |
| (선택) 품질 대조 | SWE-bench 계열 과제를 단독 vs 2인 협업 조건으로 — agent-cli의 SWE-bench 하네스 재활용 가능(03 §5.2) | 신규 |

주의: 모의 LLM 실측과 실 LLM 실측(1.35×)을 구분 보고. 결정적 재현 가능성을 강점으로 명시.

### 4.2 사용자 연구 (논문 2)

**설계 A — 통제 실험 (CHI/CSCW 스타일)**
- 참가자: 개발자 페어 N≈16–24쌍 (within-subjects).
- 조건: (C1) 메신저형 비동기 위임 모사(태스크 발사→결과 회신), (C2) 공동 세션-직렬(v0.1 FIFO), (C3) 공동 세션-병렬(v2). 순서 카운터밸런싱.
- 과제: 중규모 리포의 버그 수정 + 기능 추가 혼합(추론/파일수정 혼합비 통제).
- 측정: 완료 시간·품질(테스트 통과), 개입 빈도·지연(로그), 제동 행동(SWE-chat 대비), 중복/충돌 지시 발생률, workspace awareness 설문(Gutwin 기반), NASA-TLX, 반구조 인터뷰(grounding 격차 경험).
- 조작 점검: C3에서 TTFT 독립성이 실제 체감되는지.

**설계 B — 비대칭 grounding 집중 실험 (RQ4)**
- A가 20–30분 세션 진행 후 B가 중간 투입. 투입 시 제공 정보 3수준(없음 / 전체 replay / 요약+귀속 뷰). B의 상황 이해 정확도(퀴즈), 첫 유효 개입까지 시간, 오개입(에이전트가 이미 한 일 재지시) 빈도 측정.
- Daryanto의 HHAI-shared 조건 발견(peer accountability)과 직접 대화 가능한 설계.

**설계 C — 현장 관찰 (보강)**
- 소규모 팀 1–2주 실사용(Lehmann et al.의 방법 차용: 로그 + 인터뷰). 세션 로그(seq 정렬 다중 화자 트랜스크립트)가 그대로 분석 데이터가 되며, **익명화 후 공개하면 최초의 다중 인간-에이전트 세션 데이터셋**(04 §7.7).

### 4.3 측정 지표 요약

- 시스템: TTFT 및 TTFT~L 기울기, 처리량, 부수효과 위반률, 락 대기 시간, 공정성(사용자별 대기 분산).
- 인간: 과제 성과, 개입/제동 빈도·성공률, 중복 작업량, awareness·TLX 설문, grounding 격차(이해 퀴즈·오개입), 인터뷰 질적 코딩(articulation work 유형).
