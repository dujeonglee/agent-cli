### Round-3 신규 지적

**R3-W1 (결정 축, 변동 없음). 스터디는 설계가 아니라 실행이 필요하다.** §6.11의 "designed and ready to run, … we do not claim its result in advance"는 정직하지만, 심사표의 인간 증거 칸은 여전히 비어 있다. 프로토콜 v2의 설계 논리(기계가 재는 양을 재지 않는다, 로그는 정답지다)는 실행되면 방법론 강점으로 읽히겠으나, 실행 전에는 점수를 움직이지 못한다. CHI를 유지하려면 이 항목이 유일한 관문이고, UIST(G-b)라면 현 상태로 충분하다. **선택 모듈(미스코핑 탐지)은 채택을 권한다** — §6.7 완화의 '필요성', §7.3의 첫 데이터, §7.5 표의 예각화가 걸려 있고, 마지막 순서 배치로 편향이 보수적 방향이다.

**R3-W2 (논문-시스템 불일치, 새 발견). 논문의 헤드라인 완화책이 시스템 기본값에서 꺼져 있다.** §6.7은 스코핑 없이 통상 작업의 40턴 중 31턴이 오염됨을 보였고, 켜면 0/80이며, 비용은 프롬프트 한 절이고, 측정된 부작용은 없다(자기 과제 완수 상승, 턴 스팬 감소). 그런데 구현은 `turn_scoping: bool = False`(`loop/state.py:88`) — **병렬 계약에서도 기본 꺼짐**이다. 리뷰어 문장으로: *"저자들은 기본 설정이 통상 동시 작업의 78%를 오염시킴을 측정해 놓고 그 기본 설정을 그대로 배포한다. 완화책이 논문이 주장하는 만큼 무해하다면 왜 기본값이 아닌가? 무해하지 않다면 §6.7이 말하지 않은 비용은 무엇인가?"* 이 질문에는 좋은 답이 하나뿐이다: 병렬 계약에서 기본 켬으로 바꾸고, 절제용 `off` 스위치를 남기고, §5·§6.7의 서술을 "기본값"으로 갱신하는 것.

**R3-W3 (실증 공백, 새 발견). §6.4의 disjoint 축이 죽어 있고, 논문 자신의 완화책이 되살릴 수 있다.** 현재 서사: 원 측정의 disjoint/workspace 셀은 유효 n=2, 수리 후 재실행은 6/6 오염으로 유효 셀 0, 그래서 "재현 불가능한 조건의 원 수치를 유지"(§6.4, 감사 문서의 '재검증 불가' 항목). 리뷰어는 여기서 멈추지 않는다: **§6.7이 스코핑으로 오염을 0/80까지 제거했음을 보인 이상, 스코핑을 켠 disjoint 재실행은 의도한 경로 조건을 복원할 수 있다.** 측정 대상(효과 시간 점유율, 락 대기, 병렬도 항등식)은 락의 속성이지 프롬프트의 속성이 아니므로 스코핑 추가는 교란이 아니다. 이 재실행이 성공하면 "조건을 재현할 수 없었다"가 "완화책이 조건을 복원했다"로 바뀌고, n=2 셀도 정상 표본으로 교체된다.

**R3-W4 (일반화 한계, 심화). 모든 라이브 수치가 한 모델·한 엔드포인트에서 나왔다.** 논문은 §6.7과 Limitation 3에서 이를 스스로 말하지만, 스코핑 '준수(compliance)'는 모델의 속성이라는 점에서 이 한계는 다른 라이브 수치보다 무겁다 — 락 대기나 토큰 비율은 모델이 바뀌어도 기제가 같지만, 프롬프트 지시를 따르는지는 모델마다 다르다. 두 번째 모델에서 off/on 팔 n=20이라도 있으면 "one model" 헤지가 "two models"로 바뀐다. 없으면 현 헤지를 유지하되 Limitation 3에서 이 비대칭(구조적 수치 대 준수 수치)을 명시하라.

**R3-W5 (검증 가능성 소실). 스코핑 팔 80턴의 텍스트 수준 판정은 커밋 데이터로 불가능하다.** 2차 Q5("40개 트랜스크립트로 텍스트 수준 집계도 공짜로 되지 않느냐")에 대해 논문은 §6.6 압축 런의 21/42로 답했는데, 그것은 다른 워크로드다. 확인 결과 `out/n3c-scoping-real.jsonl`은 파일 경로만 기록하고 응답 본문을 남기지 않으므로 사후 분석이 불가능하다. 대응은 둘 중 하나: 향후 라이브 런(R3-W3의 재실행 포함)에서 턴별 응답 텍스트를 산출물에 보존하도록 하니스를 고치거나, 아니면 "이 워크로드의 판정 기준이 부작용인 이유"(파일 쓰기 과제라 텍스트 마커가 정의되지 않음)를 본문에 한 문장으로 적어 질문을 닫아라.

**R3-W6 (방법론 질문, 새로). 두 배선 버그는 모두 우연히 발견됐다 — 계약 불변식의 프로덕션 경로 커버리지를 체계적으로 감사했는가?** thread-local 귀속 버그는 라이브에서 우연히, 원자 커밋 미배선은 다른 목적의 계측 작업 중에 발견됐다. §5의 교훈("직렬 실행이 옳아 보이게 만드는 경로에 숨는다")은 정확하지만, 그 교훈의 논리적 귀결은 **§4의 불변식 각각에 대해 '유닛테스트만 있는가, 프로덕션 seam을 관통하는 테스트가 있는가'를 표로 만드는 것**이다. 세 번째 미배선이 없다는 주장은 현재 부재 증명이 아니라 미탐색이다. 감사를 수행하고 §6.11에 한 문단으로 보고하면 이 논문의 자기 검증 서사가 완결된다.

**R3-W7 (소수 표본 셀). §6.8 라이브 팔이 팔당 2회다.** 33,000×라는 인상적인 배율이 n=2에 얹혀 있다. 방향은 기제상 의심할 이유가 없으나(대기 시간이 실제 턴 길이에서 직접 나온다), 반복 3~5회면 이 지적은 사라진다. 저비용.

**R3-W8 (프레젠테이션 잔여).**
- §5의 원자 커밋 공개 문단이 약 500단어 한 덩어리다. 발견/수리/재검증(목)/재검증(라이브)/교훈으로 분할하라.
- 초록: 첫 수치에 검증 등급 마커, 마지막 문장을 완화 결과(0 of 80)로 끝내라는 2차 제안 미반영.
- §6.7의 honor 팔 "each of 500 concurrent turns" 산술(5회 × 100턴)이 여전히 암묵적 (2차 Q6).
- 참고문헌: [3] "Baumann et al." 이름 미완, [25] venue 플래그, [7]–[9] 연도·상세 불균일.
- Table 1 렌더링 [NOTE], 익명화(제목의 Coagora), venue 서식 — 전부 venue 확정 대기로 이해하나 목록은 유지한다.
- 분량: §6이 10개 RQ에 하위 실험 다수. CHI라면 §6.5·§6.9의 상세와 §6.1의 부축 일부는 부록행 후보다.

- **K2. 계약 불변식 → 프로덕션 seam 테스트 감사** (R3-W6). §4의 불변식을 열거(스냅샷 읽기, 원자 블록 커밋, FIFO 무추월, per-user 게이트, seq 할당 지점, 스트라이프 append 락, 인터럽트 소유권, 스코핑 절 재부착, id 재도출)하고 각각에 대해 "유닛만/seam 관통"을 판정. 공백이 있으면 회귀 테스트 추가. 결과를 §6.11 한 문단으로. *감사 자체는 read-only이므로 Phase A에서 시작 가능, 테스트 추가는 K 규칙 적용.*

### Track J — 기계로 닫는 실증 (라이브, 엔드포인트 공유 → 반드시 순차 실행)

- **L5.** 분량 전략 메모: CHI 확정 시 §6.5·§6.9 상세와 §6.1 부축 일부의 부록 이동안 작성 (이동 자체는 venue 확정 후).

### Track M — 사람이 해야 하는 것 (관문)

- **M1. First-use study 실행** (R3-W1 — CHI의 유일한 관문). `18-…v2` 프로토콜대로: 파일럿 1팀 → 4~6팀. **선택 모듈(미스코핑 탐지)은 채택 권고 확정** — 동의서에 열화 설정 고지 1줄 추가. 완료 시 §6.12(또는 §7 개편)로 편입, 미달(4세션 미만) 시 부록 pilot observations + venue G-b 확정.
- **M2. Venue 확정 → 서식 정규화·익명화·[NOTE] 제거.** G-c(병행) 유지 시에도 제출 시점에는 하나를 골라야 한다.

### 실행 순서

| Phase | 내용 | 의존/차단 |
|---|---|---|
| **A** | L1–L4 + K2 감사(판정표 작성까지) | 없음 — 즉시 |
| **B** | K1 기본값 전환 + K2 공백 테스트 추가 (코드 커밋 규칙 적용) | A의 감사 결과 |
| **C** | J1 → J2 → J3 → J4 (엔드포인트 순차 체인) → 논문 반영 + `verify_paper_claims.py` 확장 | B (J1이 스코핑 CLI 최종형에 의존) |
| **D** | M1 스터디 (파일럿 → 본 세션) | **사람: 참가자·동의** |
| **E** | M2 venue·서식·익명화 | **사람: venue 결정** + D 결과 |

Phase A–C는 기계로 닫힌다. D가 CHI 점수를 움직이는 유일한 항목이고, E는 제출 직전 마감이다.

### 이 플랜이 의도적으로 하지 않는 것

- §6의 정량 실험을 스터디에서 반복하지 않는다 (프로토콜 v2 원칙).
- 2모델 확보를 위해 외부 상용 API를 새로 들이지 않는다 — on-premise 재현성 원칙과 충돌. J2는 현 엔드포인트가 제공하는 범위 안에서만.
- 스코핑 기본값 전환(K1)을 논문 서술만으로 때우지 않는다 — 시스템이 논문과 다르게 배포되는 상태가 R3-W2의 요지다.
