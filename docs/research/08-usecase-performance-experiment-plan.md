## 1. 실험 전략 개요

논문의 주장 사슬은 세 단계이고, 각 단계마다 다른 종류의 증거가 필요하다.

| 주장 | 증거 종류 | 실험군 |
|---|---|---|
| "병렬+직렬 부수효과 계약은 응답성·정합성·일관성을 동시 달성한다" | 시스템 벤치마크 (결정적, mockLlm) | P1–P5 |
| "이점이 실제 워크로드에서 유지되고 비용이 수용 가능하다" | 실 LLM 실험 + 비용 분석 | P6–P8 |
| "다중 사용자 공유가 실제 협업 시나리오에서 가치를 만든다" | 유스케이스 기반 시연·측정 + (후속) 사용자 연구 | U1–U6, S1–S3 |

우선순위: **P2 > P1 확장 > P4 > U1/U2 시연 > P6 > 나머지**. P2(혼합비 그리드)가 논문의 가장 취약한 반론("파일 작업이 많으면 무의미하지 않나")에 대한 방어이므로 최우선.

## 2. 유스케이스 분석 (U1–U6)

각 유스케이스는 (a) 시나리오, (b) 계약의 어떤 속성이 발동되는가, (c) 측정 지표, (d) 데모/실험화 방법으로 기술한다. U1·U2는 논문 §6의 시나리오 기반 평가 또는 §1 motivating example로 직접 사용 가능.

### U1. 페어 디버깅 (2인 동시 상호작용) — 대표 유스케이스
- **시나리오**: A가 에이전트에게 실패 테스트의 근본 원인 분석·수정을 지시(장시간 턴). 30초 뒤 B가 같은 세션에서 "이 에러 로그의 의미가 뭐야?"라고 질문(짧은 추론 턴).
- **발동 속성**: 병렬 추론(B의 TTFT가 A와 독립), 스냅샷 읽기(B의 질문이 A의 진행 중 발견을 아직 못 봄 — staleness 경계 사례), 1:1 귀속(두 답변이 각자에게 배지 표시).
- **지표**: B의 TTFT, B 답변의 컨텍스트 정확도(A의 커밋 전/후 정보 반영 여부), UI 구분 오류율.
- **실험화**: mockLlm 시나리오 스크립트(P1 그리드의 서사 버전) + 실 LLM 1회 시연 녹화. **staleness가 실제로 문제가 되는 빈도**를 측정하는 것이 신규 기여 — 스냅샷 시점과 커밋 시점 사이 B가 참조한 정보 항목 수를 로그로 계수.

### U2. 인시던트 워룸 (3–4인 + 긴 진단 작업)
- **시나리오**: 장애 대응 중 리드가 에이전트에게 로그 전수 분석 지시(15초+ 턴). 동시에 팀원 2명이 각각 배포 이력 질의, 설정 파일 확인을 요청. 리드는 중간 결과를 보고 자기 턴만 인터럽트-재지시.
- **발동 속성**: cap·공정 큐(4번째 요청 대기), per-user 1활성턴, turnId 인터럽트(남의 턴 불간섭), 관전자 fan-out.
- **지표**: 사용자별 대기 시간 분산(공정성), 인터럽트 오발(다른 턴에 영향) 0건 검증, cap 초과 시 큐 대기 시간.
- **실험화**: P4(공정성)·P5(인터럽트 격리)의 시나리오 프레임. 메신저 방식과의 대비 서사가 가장 선명한 유스케이스 — 같은 시나리오를 "태그 → 3개의 독립 PR"로 수행하면 컨텍스트 분단이 즉시 드러남(정성 비교로 §1 또는 §7에 배치).

### U3. 라이브 코드 리뷰 / 멘토링 (비대칭 지식)
- **시나리오**: 시니어가 에이전트와 리팩터링 세션 진행, 주니어는 관전(optionalAuth)하다가 중간에 질문 참여.
- **발동 속성**: 관전 모드, seq 재생(중간 참여자 catch-up), **비대칭 grounding(RQ4의 현장 사례)**.
- **지표**: 중간 참여자의 상황 이해도(퀴즈), 재생 후 첫 유효 개입까지 시간, 오개입(이미 결정된 사항 재질문) 빈도.
- **실험화**: 사용자 연구 S2의 시나리오. 시스템 논문에서는 "재생 지원" 기능 서술 + 한계 논의로만.

### U4. 교육 실습 (1 강사 + N 학생, Daryanto 접점)
- **시나리오**: 강사가 세션에서 과제 골격을 에이전트와 생성, 학생들이 각자 질문 턴을 던짐. 동료 가시성 하에서 AI 답변 검증 행동 관찰.
- **발동 속성**: cap 스트레스(N>4), 공정 큐 회전율, peer accountability(RQ6).
- **지표**: 큐 대기 분포, 학생별 발화 형평성, (사용자 연구 시) AI 제안 검증 행동 빈도.
- **실험화**: P4의 고부하 파라미터(사용자 8명) + 사용자 연구 S3.

### U5. 오픈 커뮤니티 스레드 (불특정 다수, 게시판 모델 고유)
- **시나리오**: 공개 게시글("이 라이브러리 마이그레이션 도와줘")에 불특정 사용자들이 순차·동시 참여. 게스트 닉네임 귀속.
- **발동 속성**: 멤버십 없는 개방 참여, 게스트 신원(`#hex4`), suspend/resume(간헐 활동), 레이트리밋.
- **지표**: suspend→resume 시 컨텍스트 보존 검증, 장기 세션 compaction 없는 컨텍스트 포화 시점(알려진 한계의 정량화).
- **실험화**: P7(세션 수명·포화). 위협 모델(임의 사용자의 코드 실행) 논의 필수 — 논문 Limitations 소재.

### U6. 교차 직군 협업 (PM/디자이너 + 개발자, Ace의 목표 지점)
- **시나리오**: PM이 자연어로 요구 명세를 다듬는 턴, 개발자가 구현 턴을 병행. 서로의 출력을 실시간 관찰.
- **발동 속성**: 비개발자 참여 장벽 제거(메신저 방식의 플랜·리포 연결 요구와 대비), 이질적 턴 혼합(추론형+파일수정형 — P2의 혼합비 실측과 직결).
- **지표**: 직군별 개입 빈도, 턴 유형 혼합비 분포(실사용 로그 기반 — P2 그리드의 현실적 파라미터 근거).
- **실험화**: 현장 관찰 S1에서 수집. 시스템 논문에서는 motivating 시나리오로만.

## 3. 성능 실험 (P1–P8)

### P1. E-HOL 확장 — 3계약 TTFT 그리드 (기존 하네스 확장)
- **설계**: 계약{직렬, 거부+재시도, 병렬} × 선행 작업 길이 L{2, 6, 15, 30s} × 반복 60. 기존 e2-hol.mjs에 L=30s 추가(장시간 빌드 대표).
- **지표**: 후속 사용자 TTFT 중앙값·p95, TTFT~L 회귀 기울기(핵심), CDF.
- **가설**: 기울기 병렬 0.000 유지, L=30s에서 배수 ~125×.
- **상태**: 하네스 존재. 소요: 파라미터 추가만.

### P2. 워크로드 혼합비 그리드 — 이점의 경계 매핑 (신규, 최우선)
- **동기**: 알려진 최대 반론. E2-B에서 전원 파일 수정 시 1.07×로 붕괴함을 이미 알고 있음 — 붕괴가 **어디서 시작되는지**를 함수로 보여야 방어가 완성된다.
- **설계**: 동시 턴 2개, 부수효과 비중 m ∈ {0, 25, 50, 75, 100}%(툴콜 수/총 스텝으로 통제, mockLlm 시나리오로 결정적 재현) × 락 입도{sandbox, 충돌 단위} × 충돌률 c ∈ {0(서로 다른 파일), 50, 100%(동일 파일)}.
- **지표**: TTFT, 턴 완료 시간, 락 대기 시간 총합, 유효 병렬도(중첩 실행 시간/총 시간).
- **가설**: (i) m=100·c=100에서 1.0×로 수렴, (ii) 충돌 단위 락은 c=0이면 m=100에서도 병렬 이점 보존 — **계층 락(v2)의 존재 이유를 실증하는 그림**, (iii) 붕괴 경계는 m·c의 곱에 근사.
- **상태**: 신규. e2-hol.mjs 시나리오 파라미터화로 구현(하네스 골격 재사용).

### P3. 락 입도 ablation 확장 (E1 확장)
- **설계**: 락{없음, sandbox 전역, 충돌 단위} × 충돌 패턴{동일 파일 쓰기, 동일 디렉토리 내 상이 파일, 삭제(rm -r) vs 쓰기 경합, 셸 vs 파일}.
- **지표**: 무결성 위반률(마커 검사), ENOENT류 신규 레이스 발생률(FILE_DELETE 배타 설계 근거의 실증), 처리량.
- **가설**: 없음=높은 위반률, sandbox=0% 위반이나 처리량 최저, 충돌 단위=0% 위반 + 비충돌 워크로드에서 처리량 회복. 삭제 배타를 풀면 ENOENT 레이스 재현(주석의 주장 검증).
- **상태**: e1-ablation.mjs + `LOCK_SCOPE` 스위치로 대부분 커버. 삭제 경합 시나리오만 추가.

### P4. 확장성·공정성 — 사용자 수와 cap 민감도 (신규)
- **설계**: 동시 사용자 N ∈ {2, 4, 8} × cap ∈ {2, 4, 8, ∞} × 워크로드(U2 워룸 프로파일: 1 장기 + N−1 단기).
- **지표**: 사용자별 대기 시간 분산(Jain fairness index), 큐 체류 시간 분포, per-user 게이트에 의한 기아 방지 검증(한 사용자가 연속 5건 적재 시 타 사용자 지연), 서버 자원(메모리·프로세스 수).
- **가설**: per-user 1활성턴 + 라운드로빈으로 fairness index > 0.9 유지; cap=∞는 fan-out 부하로 p95 악화(cap 존재 정당화).
- **상태**: 신규. mockLlm 다중 클라이언트 스크립트 필요(중간 규모 작업).

### P5. 인터럽트 격리·부분 보존 (신규, 정확성 실험)
- **설계**: 동시 턴 3개 진행 중 1개를 무작위 시점 인터럽트 × 200회.
- **지표**: 비대상 턴 영향 0건(토큰 스트림 연속성 검사), 부분 본문 보존율, stale done/error 누출 0건, 세션 상태 카운트 정합(activeTurns 이벤트 vs 실제).
- **상태**: 신규지만 기존 유닛 테스트(arMux, piWorkerConcurrency)의 통계적 확장 — 저비용.

### P6. 실 LLM 검증 + 토큰 비용 분석 (신규)
- **설계**: P1·P2의 대표 셀(계약 3종 × m ∈ {0, 50, 100})을 실 LLM(예: 서버 키 1종)으로 n=30 재실행.
- **지표**: TTFT(모의 대비 순위 보존 확인), **N-병렬의 토큰 비용 오버헤드** — 스냅샷 중복 읽기로 인한 프롬프트 토큰 배수(알려진 한계 "N배 토큰 비용"의 실측 정량화; 심사자가 반드시 물을 항목), 캐시 히트 시 실효 비용.
- **가설**: 순위·기울기 결론은 모의와 동일(기존 1.35× 실측과 정합), 프롬프트 토큰은 동시 턴 수에 선형이나 provider prompt-cache로 실효 비용 절반 이하.
- **상태**: 신규. 비용 소액 발생. 논문 §6에 "모의/실측 이중 보고" 원칙.

### P7. 장기 세션 지속성 — suspend/resume·컨텍스트 포화 (신규, U5 대응)
- **설계**: 세션에 턴 200개 누적하며 (i) 매 50턴마다 suspend→resume 후 convo·파일 상태 해시 비교, (ii) 컨텍스트 길이 성장 곡선과 포화 시점 기록.
- **지표**: resume 보존율 100% 검증, 포화까지의 턴 수(모델 컨텍스트 윈도우별), 포화 시 실패 모드 관찰.
- **의의**: "compaction 부재"라는 알려진 한계의 정량화 — agent-cli의 compaction 설계(03 §4.1)를 future work로 연결하는 다리.

### P8. (선택) 과제 품질 — 협업 대 단독 (SWE-bench 응용)
- **설계**: SWE-bench Lite 부분집합을 (i) 단독 1인+에이전트, (ii) 2인 공동 세션(역할: 지시자+검증자 스크립트화 또는 실제 2인)으로 수행.
- **지표**: 해결률, 총 소요, 인간 개입 횟수.
- **주의**: 인간 요인이 개입되면 시스템 벤치마크가 아니라 파일럿 스터디가 됨 — 논문 1에는 스크립트화된 2-역할 시뮬레이션만 싣고, 실인간 버전은 논문 2(사용자 연구)로. agent-cli의 SWE-bench 하네스(03 §5.2)를 Aidit로 이식하는 공수가 있어 우선순위 최하.

## 4. 사용자 연구 로드맵 (논문 2용 — 요약)

06 문서 §4.2의 설계를 유스케이스에 연결한 것. 논문 1 제출 후 착수.

- **S1. 현장 관찰**(U6 기반): 소규모 팀 1–2주 실사용, 세션 로그(seq 정렬 다중 화자 트랜스크립트) + 인터뷰. 턴 유형 혼합비 실측 → P2 파라미터의 생태학적 타당성 근거 확보. 익명화 공개 시 최초의 다중 인간-에이전트 세션 데이터셋.
- **S2. 비대칭 grounding 실험**(U3 기반, RQ4): 중간 투입 시 제공 정보 3수준(없음/전체 replay/요약+귀속 뷰) — 이해도 퀴즈·첫 유효 개입 시간·오개입률.
- **S3. 조건 비교 실험**(U1·U2 기반, RQ5–7): 메신저형 위임 모사 vs 공유 세션 직렬 vs 병렬, 페어 16–24쌍 within-subjects. 제동 행동·중복 지시·awareness 설문·TLX.
- 공통: IRB, 로그 익명화 방침 선행 수립.
