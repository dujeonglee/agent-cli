# 정보원 목록 (`## Web Sources`) — 설계 (v10.57.0)

> 상태: **출시** (v10.57.0, 2026-10-18). 앞선 단계: v10.52.0 fetch JSON·XML·charset,
> v10.56.2 무표시 절단 제거, v10.56.3 위장 차단 감지, v10.56.4 표·Gerrit·gitiles.

## 1. 왜

모델은 웹에서 사실을 찾을 때 검색 엔진부터 연다. 검색 엔진은 자동 요청에 봇 확인을
돌려주거나(DuckDuckGo 202, Google 은 JS 껍데기) 결과가 크다. 같은 사실을 **브라우저 없이
JSON·평문으로 바로 주는** 엔드포인트(Wikipedia REST, PyPI, OSV, arXiv …)가 있는데
모델이 모른다. 목록을 보여 주면 첫 호출부터 그리로 간다.

## 2. 자리 — 측정으로 정함

변형 넷, 8분야 과제(검색·백과·패키지·코드·Q&A·보안·논문·데이터) × 3회, Qwen3.6-35B-A3B,
v10.56.3 고정 worktree (scratchpad `webab/`).

  그래서 NVD·PyPI 줄에 `(large: …)` 를 단다.
- 일하는 방식의 안내라 도구 설명보다 꼬리가 맞다 — Task Guidelines 를 꼬리로 옮긴
  v8.52.0 과 같은 결.

## 3. 데이터

- **기본 목록** `agent_cli/default_web_sources.json` — `{header, sources: [{id, group, text}]}`.
  `id` 는 `<그룹>.<이름>`(`vulns.nvd`), `text` 의 둘째 줄부터는 같은 칸에 이어진다.
  전부 켜짐(사용자 결정 — Wi-Fi 그룹 포함, 약 460토큰/턴).
- **사용자 변경** `.agent-cli/web-sources.json` — **바꾼 것만**:
  `{"disabled": [id], "added": [{id, group, text}]}`. 기본 목록의 사본을 두지 않으므로 다음
  버전의 새 기본 정보원·바뀐 주소를 그대로 따라간다. 기본과 같아지면 파일을 지운다.
  깨진 파일은 기본으로(런을 멈추지 않는다). 모르는 `disabled` id 는 저장하지 않는다.
- **꼬리** `web_sources.render()` — 켜진 항목을 그룹 순서로, 그룹 이름은 그룹 첫 줄에만.
  `fetch` 가 루프의 `tools_list` 에 있을 때만 싣는다(감사자 등 fetch 없는 루프 제외).
  턴마다 파일을 읽어 변경이 다음 턴부터 반영 — 시스템 프롬프트·KV 캐시는 그대로.
